## Gradle 9.4.1 升级适配：deployment.gradle.kts 的 Project.exec 迁移

- **背景**：wrapper 被外部从 8.9 升到 9.4.1（`gradle/wrapper/gradle-wrapper.properties`，未提交）。Gradle 9.0 移除了 `Project.exec` 及全部脚本级 counterpart（`Script.exec` / `KotlinScript.exec` 等，官方迁移指南 "Removal of Project#exec, Project#javaexec, and script-level counterparts"），导致 `apply(from = "deployment.gradle.kts")` 在配置阶段编译红：234 个 `Unresolved reference 'exec'`（用户报的 `deployment.gradle.kts:110:5` 是第一处）。根 `build.gradle.kts` 头部注释此前已预警过此升级后果。
- **修法**（按仓库自己注释里开的方子"先按 ExecOperations 重写"）：
  - `deployment.gradle.kts` 顶部加注入缝：`interface ExecOperationsHolder { @get:Inject val execOperations: ExecOperations }` + `val execOperations = objects.newInstance(ExecOperationsHolder::class.java).execOperations`（ExecOperations javadoc 推荐的实例化方式；javax.inject 在 Gradle API classpath 上）。
  - 29 处 `exec { ... }` 全部改为 `execOperations.exec { ... }`（ExecSpec API 与旧 Project.exec 完全一致，doLast 执行期调用，不触碰 9.4 "配置期起进程" 新 deprecation）。
  - 根 `build.gradle.kts` 的过时预警注释（"锁在 8.9 还能编译"）更新为已迁移状态。
- **验证**：`scripts/with-gradle-lock.sh ./gradlew help --console=plain` → BUILD SUCCESSFUL（55s，29 个模块全部配置通过）；`tasks --all` 确认 deployAndroid / deployIos / deployHarmony / verifyHarmony{Kexe,SharedLib,HapIntegration} 正常注册。
- **遗留**：Kotlin Hierarchy Template warning（`:feature:web`/`:component`/`:composeApp` 等多模块显式 dependsOn）为既有问题，非本次引入；AGP 8.6.0 / KGP 2.2.21 均满足 Gradle 9 最低要求（8.4.0 / 2.0.0）。
